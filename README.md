## IXP 专线到底是什么？和 IPLC、IEPL 差在哪

IXP 的全称是 Internet Exchange Point，互联网交换中心。传统 IPLC 是两地之间拉一根物理专线，点对点，贵但稳；IEPL 是二层的以太网专线，思路类似。IXP 走的是另一条路：让不同的网络（ISP、云厂商、CDN、大型企业）在同一个交换设施里互联，各网络之间通过对等互联直接交换流量。

落到 Mkcloud 这类产品上，"IXP 专线"的实际形态是这样的：商家把自己的入口 IP 只在 IXP 内部宣告（比如沪日线路的 SHIXP），这时候只有加入了这个交换中心的网络才能连到入口。国内符合这个条件的主要是阿里云、腾讯云、华为云、百度云、火山云、UCloud 这些云厂商的内网骨干。

这带来两个直接后果：

- **运营商家宽连不上**。三大电信运营商不在这个交换体系里，所以你没法从家里宽带直接连这台 VPS，必须先有一台云厂服务器做前置。
- **成本更低**。IX 带宽的接入成本低于从三大运营商买专线端口，所以同样的流量额度，IXP 产品卖得比同线路的电信入口 IPLC 便宜不少，给的流量还更多。

用一句话概括三种产品：IPLC 是封闭走廊，IEPL 是二层直连，IXP 是"一点接入、云厂内网直达"。三者没有绝对的稳定排序，比的是你的业务形态和哪种接入方式匹配。

有一点必须说清楚：**端内延迟不等于你到目标网站的完整延迟**。端内值只覆盖"云厂前置机到 Mkcloud VPS 到出口"这一段，你的用户从世界哪个角落访问你的业务、走什么路由，是另一回事。官方自己也在知识库里反复强调这一点，别被"1~2ms"冲昏头。

## 第三方实测：沪日 IXP 表现如何

光看官方参数不够，我找了一篇第三方博主（虎窝博客）对沪日 IXP 1TB 套餐的完整实测，这位博主自己配了一台腾讯云上海锐驰型做前置，数据有 Geekbench 和完整路由记录，可信度不错。

**延迟**：腾讯云上海到 VPS 入口 ping 32ms；从日本出口向 IIJ、KDDI、中国电信 CN2、AWS Tokyo 测试，延迟稳定在 25.7~27ms 之间，抖动极小（mdev 基本在 0.2ms 以内）。这个数字和官方标的 25~28ms 完全对得上，没有虚标。

**带宽**：到东京 GSL Networks 测速点跑出 191.81 Mbps 上行 / 183.79 Mbps 下行，基本打满 200Mbps 峰值；到洛杉矶 134ms、跑 199Mbps，说明美西方向的转发能力也在。前置链路（腾讯云上海 ↔ VPS）实测 211/190 Mbps。

**IP 质量**：这是很多人关心的点。出口 IP 的 Scamalytics 欺诈值 0、AbuseIPDB 0、IP2Location 低风险，各大数据库识别为日本机房 IP。实测 TikTok、Netflix、Disney+、YouTube、ChatGPT 全部以日本原生方式解锁。不过要说清楚：官方并不承诺流媒体解锁和原生属性，这台机器测得好不代表每一台、每条线路都如此，买之前想清楚你要什么。

**性能**：2 核 EPYC、Geekbench 6 单核 1277 / 多核 2313，磁盘 4K 写 155MB/s，跑业务程序完全够用。博主也提到这机器物理上在国内，25 端口出站被阻断，不适合拿来做邮件发送之类的事。

沪港方向的第三方反馈就没这么漂亮：有测评指出国际上传限速 100M，出口 IP 也基本被识别为机房 IP。Nodeseek 上还能找到用户打折转卖深港 IXP 的帖子，理由是机器出了问题、工单和群消息没人回。把正反两面都摆出来，你自己判断。

## 常见问题

**IXP 专线是不是假专线？**
不是。它是在交换中心层面实现的对等互联接入，只是不是 IPLC 那种点对点物理专线。延迟数据、IP 独立性和出口质量都是真实的，代价是入口只对云厂网络开放。

**没有云服务器能用吗？**
不能。入口仅允许云厂 BGP 网络连入，你需要至少一台支持范围内的云主机做前置，这笔钱要算进总成本。

**超流量了怎么办？**
计量型套餐双向统计，超量后停机。可以后台自助购买流量重置，或者提工单补差价升级到更高档位。

**能用它解锁流媒体或拿原生 IP 吗？**
官方不做任何承诺。第三方实测中沪日方向确实出现过流媒体全解锁、IP 风险值极低的情况，但这属于"测到是赚到"，下单决策不应建立在这上面。

**年付划算多少？**
以沪日 1TB 档为例，年付 1188 元折合约 99 元/月，比月付档位低不少；深港 2TB 年付约 97 元/月。如果线路验证过没问题，年付是更优解，但考虑到 24 小时退款窗口，建议先用月付跑一两个月的真实业务再转年付。
